A map is part of the work.

These notes are about the practice. They do not describe a client.

Note 01

Read paths, not rumors.

The first week is for the system as it is. Follow one task from the screen to the data and back. Write the path in plain sentences. Opinions about a rewrite can wait until that path is on paper.

Note 02

A constraint you hide will arrive later.

If a date, a library, or a rule limits the work, name it in the first note. A team can plan around a limit it can see. It cannot plan around a limit that shows up in the last week.

Note 03

Steady, then clear.

A clear screen on a shaky system is a poster. Make the system hold. Then remove the words and controls that hide what it is doing. The interface should answer a simple question: what is going on.
