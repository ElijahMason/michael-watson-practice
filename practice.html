Plate 02, Practice

Four rules for a change.

Michael Watson keeps these rules in front of the work. They are standards for a change, not a record of finished jobs.

  1. 01

    Read the system before changing it.

    Follow the path a person already uses. Write what the code does today before you touch it.

  2. 02

    Name the constraint.

    Say what the work will not do, in a place the next person will find. A hidden limit returns late.

  3. 03

    Leave the next person a map.

    Names, the decision, and the reason. Someone should be able to continue without you in the room.

  4. 04

    Prefer boring reliability, then make the interface clear.

    Keep the system steady. Then make the screen say what is happening. Clarity is the second pass.

Held in view

Ship the smallest true thing.

Reliability comes before a clearer screen. A clearer screen comes before a new idea.
